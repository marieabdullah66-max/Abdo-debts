# Abdo Debts — V36

برنامج مستقل لإدارة مديونيات الموردين، مبني بنفس فلسفة Abdo Supply لكن بقاعدة بيانات ومشروع منفصلين.

## الموجود حاليًا

- موردون مستقلون مع إضافة مورد سريعة أثناء إدخال الفاتورة.
- فروع ثابتة من الإعدادات، ويمكن إيقاف الفرع مع الحفاظ على بياناته.
- فاتورة: المورد، الفرع، رقم الفاتورة، القيمة، تاريخ الفاتورة، تاريخ استحقاق اختياري، ملاحظات، ومرفق PDF اختياري حتى 10MB.
- رقم الفاتورة فريد داخل المورد نفسه: لا يسمح النظام بتكرار نفس الرقم لنفس المورد حتى لو اختلف الفرع.
- سداد نقدي أو مصرفي. عند السداد المصرفي يطلب اسم المصرف فقط.
- السداد الواحد يخص موردًا واحدًا وفرعًا واحدًا، ويمكن توزيعه يدويًا على عدة فواتير داخل نفس الفرع.
- سداد جزئي مع حساب المتبقي وحالة الفاتورة تلقائيًا: غير مسددة / جزئي / مسددة.
- تعديل وحذف السداد حسب الصلاحية، مع إعادة حساب أرصدة الفواتير تلقائيًا.
- مستخدمون بصلاحيات منفصلة، ومستخدم يمكن ربطه بفرع واحد أو عدة فروع أو كل الفروع.
- Dashboard لإجمالي الفواتير، المسدد، المتبقي، المتأخر، وحالة الفواتير، وأعلى الموردين مديونية والمديونية حسب الفروع، مع Aging للرصيد المفتوح (غير مستحق / 0–30 / 31–60 / 61–90 / +90 يوم).
- صفحة الموردين تعرض Aging لكل مورد بعدد الأيام منذ أقدم فاتورة ما زال عليها رصيد، ويتبع فلتر الفرع.
- صفحة مستقلة لخطة السداد: مواعيد ومبالغ مخططة، تأجيل مع سبب، متابعة المتأخر ومستحق اليوم والأسبوع القادم، وربط الموعد بالسداد الفعلي.
- قسم مستقل لحركة الأصناف: دليل أصناف مركزي، رفع تقرير CSV التفصيلي الموحد من منظومة البيع (مع دعم Excel القديم في الخلفية)، تجميع صافي المبيعات، تحويل الفرط إلى علب، وحساب معدل البيع اليومي لكل صنف حسب الفرع والفترة.
- الأسماء المختلفة بين تقرير البيع ودليل الأصناف يمكن مطابقتها مرة واحدة، ويحتفظ النظام بالمطابقة للتقارير القادمة.
- PWA مناسب للهاتف.

> اسم **Abdo Debts** مؤقت ويمكن تغييره لاحقًا بدون تغيير منطق البرنامج.

## إنشاء مشروع Supabase جديد

1. أنشئ مشروع Supabase مستقل عن Abdo Supply.
2. افتح SQL Editor وشغّل الملف `supabase/schema.sql` كاملًا.
3. انسخ `backend/.env.example` إلى `backend/.env` وضع مفاتيح المشروع الجديد:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=...
SUPABASE_SECRET_KEY=...
```

يستخدم الـBackend مفتاح الخدمة للعمليات المالية، بينما الواجهة لا تتصل بقاعدة البيانات مباشرة.

## إنشاء أول مدير

بعد تثبيت المتطلبات وضبط `.env`:

```bash
python scripts/create_admin.py admin "مدير النظام" "StrongPassword123"
```

بعد الدخول كمدير، أنشئ الفروع وباقي المستخدمين من الإعدادات.

## التشغيل محليًا

```bash
pip install -r requirements.txt
python run.py
```

ثم افتح `http://127.0.0.1:8000`.

## النشر

هيكل التشغيل متوافق مع نشر FastAPI المعتاد، ويوجد `app.py` في جذر المشروع كما في Abdo Supply. ضع متغيرات البيئة الثلاثة نفسها في منصة النشر.
